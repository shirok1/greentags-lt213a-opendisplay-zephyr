# T5 屏幕驱动

[文档导航](README.md) · 实现：[epd.c](../src/epd.c)

本驱动针对 GDEW0213T5 的 104×212 单色面板。全刷使用面板厂家初始化序列，局刷使用 T5 示例的寄存器 LUT 并根据实板校准驱动帧数。其他 2.13 寸面板、T5D 或通用 InkyPHAT 参数不能直接视为等价。

## 数据与电气时序

OpenDisplay 图像逐行、MSB first、0 黑 1 白。全屏 2,756 B；局部更新先旧平面后新平面，X 和宽度按 8 像素对齐。旧/新图与 etag 的关系见[协议](protocol.md)。

软件 SPI 使用 mode 0，最小半周期 1 µs，保持中断可响应以优先满足 BLE。数据块内保持 CS 有效，命令和局部平面边界重新选通。局部模式由固件取反 wire 像素后写入 `10 / 13`，客户端保持标准极性；平面长度按实际矩形宽高计算。

BUSY 物理低为忙、高为就绪。上电/关电命令后先等待 10 ms，刷新命令后等 100 ms 再轮询；每次等待上限 30 秒，就绪后保留 10 ms 稳定余量。这些值要结合失败清理的总时长评估，不能把单次 BUSY 超时当作整条调用的上限。

100 ms等待与面板执行刷新重叠，缩短它不会等量加速。缩短BUSY轮询间隔也不能缩短波形；
当前保留10 ms轮询和就绪余量。软件等待的收益边界见 [性能](performance.md)。

## 全刷、fast 与局刷

| 模式 | 驱动行为 |
| --- | --- |
| 全刷 | 初始化全屏模式、旧平面填白、写新平面、刷新、关电 |
| 全屏 fast（mode=1） | 当前与全刷使用相同 SPI 序列，不提供独立加速波形 |
| 局刷 | 初始化 T5 寄存器 LUT、设置窗口、写旧/新平面、刷新并退出局部模式 |

raw 全屏 PIPE 收齐后自动按 full 刷新。比较 full/fast 应用压缩 PIPE 和显式 END，否则 selector 根本没有机会生效。

项目固定的上游 bb_epaper 中，宣告的 panel_ic=19 对应 `EP213_104x212`，没有独立 Fast 初始化，fast 同样回退 full。这里的兼容是相对行为一致，不表示本机寄存器值与上游通用初始化完全相同。[上游面板表](https://github.com/bitbank2/bb_epaper/blob/5dccfbbf553a9b0fe2547cbc4e60138e1ff2fb43/src/bb_ep.inl#L4092)、[刷新回退](https://github.com/bitbank2/bb_epaper/blob/5dccfbbf553a9b0fe2547cbc4e60138e1ff2fb43/src/bb_ep.inl#L4820-L4839)。

full与fast的相同驱动序列也由主机测试验证。真正加速需要独立LUT或PLL帧率方案，
并同时校准黑→白、白→黑、残影、温度与电压；完成通知只能说明驱动流程完成。

## 局刷帧数为什么是配置项

五张 LUT 对应 VCOM、白→白、黑→白、白→黑、黑→黑。当前保持五表时序一致，指定驱动阶段默认 100 帧。其余阶段、过渡方向、电压和 PLL 不随这个值变化。

早期厂家示例的 14 帧在测试板上留下旧字，且白→黑也不完整。仅增强黑→白不足以解决双向转换；五张表统一 100 帧后，正向与反向数字更新均完整，仍有轻微残影。改为全高扫描没有改善，已恢复窗口扫描。参数校准必须同时观察两种颜色转换，不能只看“旧字淡了”。

```sh
uv run --locked python scripts/set_partial_frames.py
uv run --locked python scripts/set_partial_frames.py 'DEVICE_ADDRESS'
uv run --locked python scripts/set_partial_frames.py 'DEVICE_ADDRESS' 160
uv run --locked python scripts/set_partial_frames.py 'DEVICE_ADDRESS' --reset
```

值保存在标准 DataExtended 的 `custom_string_3`，格式为 `lt213a.partial_frames=160`。这是本项目约定，没有新增 TLV。支持整数 1–255；每次 `epd_region()` 读取已提交配置，下一次局刷生效。缺少字段、不相关字符串、非法数字或越界值回退 100。范围表示寄存器可表达值，不表示所有值均已完成光学验证。

工具保留其他配置，写前备份到 `build/partial-frame-backups/`、写后重连比对；已有不相关 `custom_string_3` 内容时拒绝覆盖，reset 也不会清除别人的值。认证设备可用 `--key-file PATH`。旧固件即使能存这个字符串，也不一定消费它。

## 画质与速度如何取舍

同一数字窗口的目视校准支持以下取舍；应在实际面板、图片和环境上复核：

| 策略 | 目视结果 |
| --- | --- |
| 单次100帧 | 数字完整，轻微残影 |
| 单次160帧 | 更干净 |
| 先白100，再目标100 | 对照中较干净、笔画正常 |
| 先目标反色，再目标 | 不如先白策略 |

两步策略由客户端发出两次标准局刷，每步都等完成并更新 etag；固件不会把普通请求暗中变成两刷。测试入口：

```sh
uv run --locked python tests/test_partial_hardware.py DEVICE BEFORE.png AFTER.png --white-first
```

图片必须预先为 104×212 原生方向。`--invert-first` 表示先写**目标图**在差异窗口内的反色。测试先全刷建立基准，再执行局部请求。

在固定局刷窗口下，100→160帧会增加约1.2秒驱动时间；该参数只作用于局刷LUT，
不会加速全刷。帧数持久化与生效由实机测试覆盖，不能替代对应面板的目视校准。

厂家示例建议周期性全刷消除累积残影；本固件不自动计数强制全刷，客户端应安排全刷。此前参考建议为每五次局刷一次，但实际间隔仍应按面板、图案和温度确认。

## 休眠与验证边界

成功关电后默认发送 `07 A5` 深睡并断开 BUSY 输入缓冲，下一次传输恢复输入并 RESET 唤醒。BUSY 超时不会提前深睡；重复成功关电不再发送 SPI。仅关电对照构建使用 `--no-epd-deep-sleep`。完整电源策略见[电源与稳定性](power.md)。

GPIO 主机测试检查真实驱动的字节序列、非正方形窗口、平面边界、像素极性、五张 LUT、两种休眠配置和超时恢复；它不证明实际引脚波形与画质。`00 73` 也只表示驱动流程成功。长期残影、低电压、全温区及独立供电下反复深睡唤醒仍需实物测试。

全刷来源为厂家 2019-10-16 示例，局刷来源为 GDEW0213T5 Arduino P20201021；历史核对使用 T5 专用规格与 IL0373 资料，原附件不随仓库提供。许可和来源说明见 [NOTICE](../NOTICE.md)。
