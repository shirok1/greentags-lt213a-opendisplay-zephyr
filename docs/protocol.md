# 协议与配置事务

[文档导航](README.md) · 实现：[protocol.c](../src/protocol.c)、[config_store.c](../src/config_store.c)

本项目实现固定 LT213A 硬件上的 OpenDisplay 子集。兼容性目标是标准客户端可以发现、读配置、上传和认证；不会为了复制上游宽松处理而取消长度、CRC 或硬件约束。

## 连接与命令

服务和特征 UUID 均为 `00002446-0000-1000-8000-00805f9b34fb`。先订阅通知，再写命令；业务请求以 `00 opcode` 开头。普通 ACK 为 `00 opcode`，NACK 为 `ff opcode`，部分命令带错误码或数据。认证错误有单独格式，见[认证与加密](security.md)。

| 命令 | 用途与边界 |
| --- | --- |
| `40` | 配置读取，编号分块；首包包含总长度 |
| `41 / 42` | 配置写入/续传，容器最大 768 B |
| `43` | 版本；响应为 ACK、opcode、major、minor、SHA 长度、SHA、patch |
| `44` | 触发遥测采样并返回 16 B MSD；失败 NACK |
| `45` | 提交清除事务，恢复内置默认配置 |
| `50` | 双向认证；启用后大多数业务命令须加密 |
| `70 / 71 / 72` | direct 图像开始、数据、结束 |
| `73 / 74` | 刷新成功/失败通知；END ACK 之后才知道刷新结果 |
| `76` | direct 局部更新，检查区域和 etag |
| `80 / 81 / 82` | PIPE 开始、带序号数据、结束 |
| `0f` | 中止并复位 |
| `52 / 53`、外设命令、OTA | 本板无对应关机/唤醒硬件、外设或 OTA 布局，返回不支持 |

版本 SHA 来自构建时 Git HEAD 的前 12 位，无 Git 环境为 `unknown`。它不能标识未提交改动，测试版本还应记录二进制哈希。

全屏为 104×212，13 B/行，共 2,756 B，逐行、高位在前，0 黑 1 白。direct DATA 最多 230 B 数据；实际单包还受协商 MTU 与加密开销限制。zlib 采用 512 B 窗口，校验 Adler32、流结束及准确的解压长度；超量或截断不会成为成功刷新。

## PIPE：一包在途，仍支持重传

客户端请求窗口 W 和确认间隔 N，固件返回 **W=N=1**，帧上限为客户端上限与 244 B 的较小值。客户端应按返回值发送；这里没有乱序图像缓存。

SACK 报告最高连续序号和此前最多 32 帧的位图。序号是 8 位，可从 255 回绕到 0；内部另记累计帧数。已接收的近期重复帧只重发 SACK，不再次写屏。未来序号或非法数据会进入 fatal 路径，之后 DATA 静默，新的 START 可以恢复。

结束方式决定客户端是否会等待成功：

| 传输 | 结束条件 | 响应顺序 |
| --- | --- | --- |
| raw 全屏 PIPE | 准确收齐整帧后自动结束 | 尾 SACK → `00 82` → `00 73` 或 `00 74` |
| zlib 全屏 PIPE | 完整压缩流后显式 END | 尾 SACK → END ACK → 刷新结果 |
| raw/zlib 局部 PIPE | 数据完整后显式 END | 同上，成功后更新 etag |
| 活跃但不完整的 PIPE END | 不能提交 | 尾 SACK → END NACK，无成功刷新 |

raw 自动结束后再发 END 不能改变刷新模式；迟到 DATA 在没有活跃 PIPE 时静默，也不会打断新的 direct 事务。客户端不要通过禁用 PIPE 或改 SDK 常量规避这些正常语义。

本实现仍有明确收紧：W/N 为零拒绝；仅有序号的空 DATA 拒绝；raw 多余数据拒绝而不裁掉；END 只接受实现列出的长度和模式。W=1 下重复包容忍范围比窗口更宽，但不承诺上游多包乱序吞吐。新增兼容修复应围绕具体客户端行为和测试，不笼统追求所有异常输入逐字节一致。

## 局部更新与 etag

局部窗口必须在屏内，X 和宽度按 8 像素对齐，数据依次包含旧平面、新平面，总字节数为 `width / 8 × height × 2`。etag 用于确认客户端旧图与屏幕状态一致，只有刷新成功才更新；失败或中止使基线失效。

etag 只存 RAM。复位后应先完成带有效 etag 的全刷建立基线；raw PIPE 自动结束写入 etag 0，不能直接作为后续局刷的有效基线。官方 `PartialState` 可负责客户端状态管理。波形、极性和视觉质量另见[屏幕驱动](display.md)。

## 配置容器与线上分块

容器由长度、版本 1、类型化配置包和末尾 CRC 组成。CRC 为 CRC16-CCITT-FALSE：初值 `ffff`、多项式 `1021`，计算时前两字节长度置零，尾 CRC 小端。容器长度字段可以为零或准确总长。

系统、制造商、电源、显示四包必须存在且不可重复；另支持 SecurityConfig（`0x27`）和 DataExtended（`0x2C`）。未知类型、重复包、不匹配的固定接线/面板、安全 flags 非零或未终止的扩展字符串被拒绝。生成默认容器使用 [generate_config.py](../scripts/generate_config.py)，生成结果 `src/config.inc` 纳入版本控制。

读取响应最多 20 B：首包头 6 B，后续包头 4 B，客户端按块编号和实际长度重组。写入容器不超过 200 B 时用单个 `41`；更长时首个 `41` 携带 2 B 总长度与 200 B 数据，之后 `42` 每块 1–200 B。只有收齐准确总量、校验并提交成功后的最终 ACK 才代表持久化完成。配置 ACK 为两字节，客户端不应要求上游某个实现附带的零填充。

## 双槽如何保持旧配置可用

1. 选择非活动的 1 KiB 页并擦除；读操作继续返回旧配置。
2. 数据到达即按 Flash 字对齐写入该页，保留跨分块的未对齐字节。
3. 收齐后验证容器，写 generation、length 和内部 CRC。
4. 最后写 commit word，再把新槽设为活动槽。

启动扫描两槽，仅接受提交标记、内部 CRC 和容器验证均有效的槽，选择较新的 generation。没有有效配置时读取内置默认。断连、超时、坏 CRC、超出声明长度或写入失败不会把未完成槽选为活动配置。

`45` 写入零长度墓碑，立即及重启后均回到内置默认。这是逻辑清除，旧槽可能仍留有历史密钥，不能当作物理安全擦除。主机模拟故障和实机中途复位已有覆盖，真实擦写瞬间掉电仍需验证。

## “能保存”与“会生效”

| 配置 | 运行效果 |
| --- | --- |
| SecurityConfig | 控制认证、密钥、绝对会话期限 |
| DataExtended.serial_number | 提交后更新 GAP/扫描响应名称，见 [BLE](ble.md) |
| DataExtended.custom_string_3 的项目约定 | 下一次局刷加载帧数，见[屏幕](display.md) |
| 其他允许的元数据、超时、rotation 等字段 | 可以保存/回读的字段，不因此承诺动态改变硬件策略；需检查具体消费者 |

提交配置的最终响应在原会话下发送，随后主循环重置安全会话并更新名称及认证标志。修改密钥后客户端应断开并用新密钥重新建连；完整换 key 实机覆盖仍有限。

制造商默认值表示 DIY/Custom，MCU 标识为 `0xffff`，不冒充 nRF52 或注册过的产品。获得上游正式 ID 前，客户端可能显示 Unknown。
