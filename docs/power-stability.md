# 功耗与稳定性核查（2026-09-08）

范围：当前固件源码、实际构建配置、既有测试记录及一次只读 BLE 空闲连接测试。未刷写固件、未改认证配置、未测量整板电流；不能据此给出电池寿命。当前程序约 95,700 B Flash / 16,336 B RAM，静态分配外剩余 48 B，无动态堆。

## 修复进展（同日）

新增 nRF51 硬件看门狗，180 秒期限，仅主业务循环喂狗；CPU 睡眠时继续计时，调试器暂停 CPU 时停止。主循环正常最多空闲等待 60 秒，期限也留出面板 BUSY 超时及清理路径的空间。直接使用已有 Nordic HAL，未增加驱动状态或线程。致命错误处理改为冷重启；硬件 RESETREAS 保留复位原因，未增加 Flash 日志。软件复位原因本身不能区分致命错误和普通 reboot 命令。

实机加密路径暴露主线程栈不足，已限制认证/解密函数内联并重新分配既有栈空间。当前 Flash 95,788 B，RAM 仍 16,336 B。下面“待修”段落记录的是此前审计状态；整板电流、断电恢复和长期运行仍需物理实验。

### 修复版栈实测

在完整认证、错误注入、加密全刷/局刷、会话过期和配置恢复之后，通过 SWD 读 RAM，按 ELF 栈符号扫描 0xAA 前缀。主线程 1536 B 中未使用前缀 252 B，系统工作队列 1024 B 中 380 B；控制器 RX 768 B 中 532 B，优先 RX 448 B 中 196 B，ISR 1024 B 中 496 B，idle 128 B 中 84 B。线程哨兵均完整。快照 `build/auth-final-ram.bin`；这是已执行路径的水位，不是所有中断时序下的最坏情况证明。

### 硬件看门狗实测

最终 95,788 B 构建已通过 `uv run --locked python tests/test_recovery_hardware.py DEVICE`。先核对 RUNSTATUS、180 秒 CRV、RR0 和睡眠/调试暂停策略，再清 RESETREAS，通过 SWD 在未分配 RAM 注入 `CPSID I; B .`，明确让 GDB continue。等待 185 秒后读到看门狗复位原因位，WDT 已重新启动；官方 OpenDisplayDevice 无 key 重连，配置和版本读取成功。日志 `build/watchdog-hardware.log`、`build/watchdog-gdb.log`。

最初使用 detach 且尝试写 GDB 未提供的 PRIMASK 寄存器的脚本没有验证到复位，已废弃该注入方式；不能把那次失败解释成芯片问题。最终脚本执行实际关中断指令并保持 continue，验证真正的业务卡死恢复。看门狗只由主循环在等待前后喂，避免把正常等待与较慢配置响应累加成误超时。

这项测试仍有 SWD 连接，不替代断开调试器后完整断电上电、整板电流或长期独立供电测试。此前真实栈溢出也验证了 fatal 路径会软件复位，但它不是本次硬件看门狗故障注入的复位来源。

## 已确认的设计与限制

| 项目 | 证据及判断 |
| --- | --- |
| 空闲等待 | `src/main.c` 使用信号量/截止时间等待，构建启用 `CONFIG_TICKLESS_KERNEL`；不是应用线程一直轮询，但无线及时钟事件仍唤醒 CPU。 |
| 广播 | 启动 10 秒使用 160 ms，随后 1 秒，0 dBm；代码见 `src/main.c:75`。快/慢切换参考官方 nRF 实现，不等于已经测过耗电。 |
| 连接 | 业务空闲 120 秒主动断开；版本查询不续期。未启用 GAP 主动连接参数更新，实际间隔由中央设备决定，不能把构建里的偏好 30–50 ms 当作实际协商值。 |
| RC 时钟 | `build/zephyr/.config` 的校准周期为 4000 ms，跳过计数为 1；时钟驱动会请求 HF 晶振并通过系统工作队列测温，必要时校准。因此应用 MSD 五分钟测温不等于芯片五分钟才测温。不能为省电直接关闭 BLE 所需校准。 |
| 屏幕关电 | `src/epd.c:161` 发 `50 F7 / 02` 关闭屏幕内部高压；没有切断整块屏的供电。`07 A5` 深睡是已有实验开关，当前未启用。BUSY 默认仍接输入，是否存在漏电应实测。 |
| 双阶段局刷 | 先白 100 帧、再目标 100 帧约 5.8 秒，两次启动/刷新/关电。BLE 字节少不代表整板耗电一定低于全刷；需积分比较每次刷新电荷。 |
| Flash/BLE 协调 | 当前配置 `CONFIG_SOC_FLASH_NRF_RADIO_SYNC_TICKER=y`，采用 Zephyr 无线同步 Flash 驱动；避免把裸 NVMC 阻塞写入的风险直接套用。但真实弱电/掉电与 BLE 同时操作尚未验证。 |

## 应优先补齐的稳定性项

1. **致命错误后没有自动恢复。** 当前 `CONFIG_WATCHDOG` 未启用，也未覆写 fatal handler。固定 Zephyr 默认 `arch_system_halt()` 关中断并无限循环；栈哨兵能发现错误，但不会使设备恢复，反而可能持续耗电直到重启。建议增加硬件看门狗和明确的 fatal 恢复策略，并保留重启原因。喂狗应反映主业务线程真实推进，不能仅由一个独立定时线程无条件喂狗，否则无法发现主线程卡死。[实际默认实现](https://github.com/zephyrproject-rtos/zephyr/blob/9f824289b28d7aea2eee74f62787c385a5005453/kernel/fatal.c#L21-L45)、[官方 fatal 文档](https://docs.zephyrproject.org/3.7.0/kernel/services/other/fatal.html)。
2. **看门狗阈值必须覆盖真实合法等待。** 单次 BUSY 等待为 30 秒，但初始化/刷新失败后还会尝试关电，关电可再等 30 秒；之后 abort 还可能再次尝试关电。不能简单设置 30 秒看门狗。应先约束整条失败路径总时限，再设置阈值并验证挂 BUSY 与断线恢复。
3. **最坏栈水位未封闭。** 48 B 未分配 RAM 不是栈余量。此前版本大包测试中主线程仅有 108 B 未触碰前缀，是旧构建特定路径的观测，不能推广到当前固件或认证、Flash 错误路径。应测当前 ELF 的主线程、系统工作队列、控制器线程及 ISR 水位。新增诊断代码本身也会改变栈占用，避免直接打开重量级日志/线程分析器后把它当生产水位。[既有观测](ble-large-packets.md)。
4. **缺少长期和真实电气故障验证。** 现有模拟 Flash 测试覆盖 220 个断电点，不能替代真实棕断、擦写期间掉电、低电压刷新。需要独立供电冷启动、连续重连、主动断线、上传截断、BUSY 超时，以及恢复后再上传。

## 拔调试器与测量方法

Nordic 明确说明，nRF51 烧录后可能保持调试模式；拔线本身不是正常低功耗状态的证据。**断开调试连接后完全断电再上电，再测整板电流。** 本次没有读取调试寄存器或发 SWD 复位，以免用户已经断开后的状态被重新改变。[Nordic nRF51 电流测量指南](https://devzone.nordicsemi.com/guides/hardware-design-test-and-measuring/b/nrf5x/posts/nrf51-current-consumption-guide)、[nRF51 Reference Manual v3.0](https://docs-be.nordicsemi.com/bundle/nRF51-Series/raw/resource/enus/nRF51_RM_v3.0.pdf)。指南里的示例电流不能当作这块 Zephyr + e-paper 板的测量值。

建议在同一电压、室温、图案及无线距离下，用能捕获无线/升压脉冲的电流仪记录以下状态：

| 测量状态 | 需记录 |
| --- | --- |
| 冷启动后前 10 秒 | 启动与快广播峰值、总电荷、是否可靠出现广告 |
| 上电 30 秒后，未连接 | 至少覆盖一分钟心跳及多个 RC 校准周期的平均电流、峰值和谷值 |
| 连接空闲至主动断开 | 实际连接间隔、120 秒期间电荷、断开后是否回到慢广播水平 |
| 全刷 / 单次 100、160 帧 / 白100+目标100 | 从连接前到关电后相同时间窗积分，分别报告刷新电荷及总电荷 |
| `02` 关电与实验 `07 A5` 深睡 | 稳态差值，以及重复唤醒、全刷和局刷是否可靠 |

续航需用实测平均电流和电池有效容量估算，再考虑脉冲压降、自放电、温度和截止电压。当前没有这些数据，不给出“可用几个月”的推测值。DCDC 外围未确认，不能直接开启；无线 System OFF 会丢失 BLE 可发现性，不适合当前可随时连接的用途。

## 最小验证顺序

先修错误协议与自动恢复；用临时认证配置完成真实 SDK 加密互通，并恢复原配置。随后在当前构建测所有关键线程栈水位。最后独立供电运行至少 24 小时，周期性扫描/连接/版本查询，插入有边界的刷新和故障注入，记录失败次数、恢复时间和重启原因。24 小时是建议起点，不是可靠性认证。

电流测量应与上述功能测试分开进行，避免调试器、连续扫描或高频查询改变被测待机状态。

## 本轮实机只读测试结果

运行 `uv run --locked python -u build/idle-stability-probe.py`，使用实际 OpenDisplayDevice 自动读取配置，随后在 0、30、60、90 秒仅查询版本。120.10 秒观察到设备主动断开，随后重新连接及版本查询成功。与 `LINK_IDLE_MS=120000` 和版本查询不续期的预期一致。

原始日志：`build/idle-stability-probe.log`。本次没有刷新屏幕、改配置、切换供电或访问 SWD；没有独立确认调试器是否物理连接，故不把它称为独立电池供电或低功耗测试。仅验证一次空闲断连/重连流程，不代表长期稳定性通过。


## 2026-09-12 对齐配置（源码与主机验证，未烧录）

默认在成功关高压后发 `07 A5` 深睡，下一次传输通过 RESET 唤醒；保留 BUSY
超时不提前深睡和重复关电保护。`--no-epd-deep-sleep` 可构建仅关电的比较版本。
启动及断连后快广播为 100–150 ms、持续 30 秒，再切为固定 1 秒慢广播；
切换失败每 5 秒重试，不把一次 HCI 失败当成快广播期限结束。

遥测对齐为温度加内部 ADC VDD，在启动、快广播结束、未连接每 5 分钟及合法
`00 44` 请求时采样。请求先经过认证/解密与长度校验；测量失败回 NACK 并保留
完整旧快照。温度为半度偏置编码，VDD 为 10 mV 的 9 位编码，保留 MSD 其他
状态位。ADC 在成功或 50 ms 超时后停止并禁用；TEMP 继续使用共享驱动的互斥
与 HF 时钟管理，驱动正常返回时停止 TEMP。该驱动的事件等待没有独立超时，
卡死由 180 秒硬件看门狗兜底。移除一分钟广播心跳，但主循环仍最多等 60 秒
喂狗，不会因五分钟遥测周期导致误复位。

原文中的 10 秒快广播、实验深睡和一分钟心跳描述属于旧构建。新增遥测与默认
深睡的整板电流、反复唤醒、运行栈水位尚未实测；VDD 不等于剩余容量，不能
由本次改动推出续航提升比例。

## 2026-09-12 刷新延迟优化

BUSY 就绪后的 200 ms 固定尾延迟缩至 10 ms（`src/epd.c` 的 `READY_SETTLE_MS`），保留上电/关电后的 10 ms、刷新命令后的 100 ms、30 秒超时、100 帧 LUT 与深睡。手册更新流程以 BUSY 高作为后续操作条件；10 ms 余量仍需用户目视及全温区验证，不能仅凭刷新完成通知认定显示质量。

旧图填充和每个 `epd_write` 数据块保持 CS 有效；局刷平面边界重新选择并发送命令。SPI 半周期仍为 1 us，不关闭中断，不增加传输缓存。真实 GPIO 解码测试同时检查连续字节与最终引脚状态。测量见 [优化实测](performance-optimization-2026-09-12.md)。
