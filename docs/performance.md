# 性能与内存

[文档导航](README.md)

本板的128 KiB Flash和16 KiB RAM同时容纳Zephyr蓝牙栈、协议、安全和屏幕驱动。
优化优先保持MTU 247、认证、512 B解压历史窗口和有界错误恢复；图片和配置均流式处理，
不分配整帧缓冲或动态堆。

## 资源预算

使用 `scripts/build.py` 构建。它按ELF的实际加载地址检查126 KiB应用分区、16 KiB RAM、
复位向量和初始栈；最后两个1 KiB Flash页保留给配置事务。

GCC 15.3.1、全局O2 + LTO的参考布局为：

| 屏幕模式 | Flash B | 静态RAM B | 静态区外余量 B |
| --- | ---: | ---: | ---: |
| 默认deep sleep | 110888 | 16228 | 156 |
| power-off | 110848 | 16228 | 156 |

容量以本次构建的 `check_memory.py` 输出为准。更换编译器或修改源代码后，不应沿用此表
作为保证。静态RAM包含线程栈；静态区外余量与栈内部余量是两项不同指标。

| 栈 | 预留 B | 加密回归后未使用前缀 B |
| --- | ---: | ---: |
| main | 1280 | 176 |
| system workqueue | 768 | 252 |
| controller RX | 768 | 516 |
| priority RX | 448 | 148 |
| ISR | 1024 | 520 |
| idle | 128 | 84 |

该负载包含加密上传、配置与并发描述符读取、中途断连及重认证。线程哨兵完整，ISR不设
哨兵。填充值只说明已执行路径的栈水位，不证明最坏中断嵌套或全部故障组合安全。

## 内存为何能容纳原生蓝牙栈

Zephyr依赖保持未修改的正式tag，HAL/CMSIS通过manifest import固定。

- 控制器硬件AES承担块加密，应用CMAC/CCM无需176 B软件展开轮密钥；密码学临时对象
  的函数边界保持 `noinline`，避免LTO将大帧并入主循环。
- inflater状态为804 B。码长以4 bit保存，canonical符号按rank从两端扫描；动态头、
  stored头、trailer和正文树复用互斥存储，512 B跨块历史始终独立。
- 安全状态为64 B。challenge及其时间与已认证会话的计数器/重放窗口复用；key/id保持
  独立，最终proof生成后才切换阶段并初始化TX nonce域。
- 关闭无使用者的errno存储和Flash page-layout查询；Flash读、写、擦除不受影响。
- BLE使用ATT3、ACL TX1、Event RX2、L2CAP TX2；通知完成背压限制应用并行发送。
  RX37/TX56非对称DLE在现有RX节点预算内减少加密通知分片，见 [BLE](ble.md)。

单ACL发送缓冲有吞吐代价，不能把它视为与双缓冲等价。增加池深度、栈、日志或诊断
计数器前先构建核算。减栈必须重新覆盖对应最深调用路径，不能按平均水位直接回收。

Adler32按每字节状态上界用条件减法代替取模。双端Huffman查找避免完整符号表，兼顾
解码时间和RAM。复用的动态头在建树后不再访问；最终块结束时才初始化trailer，确保
逐字节暂停和跨块历史不会被清空。

## 刷新瓶颈

主机一次上传包含START初始化、数据传输、END确认、面板刷新/关电及完成通知。
面板全刷约3.36秒，上电和关电各约40–50 ms；屏幕数据写入累计约26 ms。
因此减少解码或SPI时间只能改善其中一部分，不能将CPU加速比直接换算成整屏加速比。

默认BUSY轮询间隔和就绪尾余量均为10 ms。刷新命令后的100 ms与面板执行波形重叠，
改成10 ms不会省下90 ms。2 ms轮询未表现出稳定的刷新收益；将就绪尾余量改成2 ms
只省约16 ms刷新/关电等待，故保留默认时序。明显加速需要独立波形及画质验证，见
[屏幕驱动](display.md)。

## 参考性能

下列数据用于定位瓶颈，不是吞吐承诺。2026-09-20，nRF51822 QFAB C0 / GDEW0213T5，
调试器供电（电压、面板温度未测）；macOS 27.0、Python 3.12.14、SDK7.14.1、MTU247，
GCC15.3.1、O2 + LTO、Zephyr4.4.2。源码为0.5.0版本号更新前的实现，默认BIN SHA-256
为 `6c75542b29840d274e7f471abedcd94ef165fc3535ad6bd1344f20c25ad5126d`。

输入为104×212文字/棋盘格：raw2756 B，512 B窗口zlib395 B。每项三次，连接发现和
认证不计入上传；计时期间没有调试访问。明文全刷用200 B分包、W=N=1及显式END；
加密和局刷使用SDK分包。两种路径的时间不能直接归因于是否加密。

| 操作 | 中位数 s | 范围 s |
| --- | ---: | ---: |
| 明文raw全刷 | 5.579 | 5.493–5.700 |
| 明文zlib全刷 | 4.018 | 4.017–4.080 |
| SDK局刷 | 2.518 | 2.488–2.520 |
| 加密raw全刷 | 4.799 | 4.535–5.012 |
| 加密zlib全刷 | 4.048 | 3.991–4.076 |
| 199 B加密配置读取 | 0.898 | 0.871–0.899 |

局刷在相同全刷建立etag后进行，差异边界为 `(33,68)` 至 `(61,78)`，右/下不包含，
由SDK对齐窗口。双端查找的独立诊断样本使文字图解码累计时间从144降至85 ms，
却未显示对应的全刷加速；这些经过时间含中断，不能称为纯CPU周期。

## 如何重新测量

1. 保存源码版本、未提交差异、工具链、ELF/map/BIN及哈希。设备版本SHA不包含未提交差异。
2. 固定图片、分包、供电、客户端和实际MTU/DLE，区分建连、传输与刷新时间。
3. 多次重复并记录失败及范围；以完成通知为协议结果，另外检查实际画质。
4. 软件阶段计时用单调时钟，诊断计数器本身的资源开销单独核算；不要在无线计时期间halt。
5. 栈采样用与设备精确匹配的ELF，跳过线程哨兵扫描填充值，记录采样前负载与复位状态。

可以用Zephyr原生 `rom_report`、`ram_report`、`dashboard` 查归属；LTO会模糊部分
源文件归属，某些工具链带WRITE标志的Flash rodata也会误入RAM报告。最终容量仍以
`check_memory.py` 为准。PC采样中的WFI比例不等于实际电流，功耗方法见 [电源](power.md)。
